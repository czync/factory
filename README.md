# Factory

Factory 是 IMSW 迁移项目的交付工作台和协调服务。它将标准迁移工作包转成工程师和 Agent 可以执行的任务，并将 Jira、GitHub PR、Harness 运行及验收证据关联到同一次交付。

当前仓库记录高层设计。模块边界、工作包和发布控制见[高层设计](docs/high-level-design.md)。

## 一次 Linux 改造如何交付

| 步骤 | 谁在哪里做 | Factory 记录什么 |
| --- | --- | --- |
| 确认范围 | 工程师在工作台确认应用、迁移路径和改造项 | 应用、Wave、模板和工作包版本、负责人与验收要求 |
| 创建并派发任务 | 工程师在工作台发起 Linux 改造。后台创建或关联 Jira Task，并将任务派到获准的执行端。需要人工启动的执行端可在 IDE 中打开任务，由 Agent 领取 | 迁移任务 ID、Jira Issue、授权范围和执行状态 |
| 执行改造 | Agent 在受控 IDE 或远程环境运行，通过 MCP 领取任务、读取应用上下文和引用的 Skills，提交草稿、问题和结果 | Agent 执行记录、工作包版本、旧系统基线引用及每次尝试 |
| 评审与构建 | Agent 或工程师在授权范围内提交 GitHub PR。人工独立 Review，Harness 执行构建和测试 | PR、实际构建的提交、Harness 运行和测试结果。通过任务 ID、PR 和提交关系自动归集 |
| 验收与推进 | 后台核对 Review、构建、基线比对及必要的人工作业证据。工程师在工作台处理缺失证据和异常 | 完成或阻塞的原因、证据来源及可开始的后续工作 |

**派发和领取属于同一条流程。** 工作台决定做哪项工作、授权谁执行及如何验收。Agent 可以由已接入的执行端启动，也可以由工程师在 IDE 中启动后通过 MCP 领取同一任务。Skills 提供版本化的方法和工具入口，实际代码工作在工程环境执行。

以迁移任务 ID 为主线，Jira Task 跟踪交付责任，PR 记录实际变更和人工 Review，Harness 提供对应提交的构建与测试证据。一个任务可关联多次 Agent 尝试、多个 PR 和多次运行。后台在工程师关闭工作台后继续同步和核对结果。

遇到实际阻塞时，Factory 创建或关联 Jira 问题，保留 **Problem → Context → Investigation → Solution → Verification**。修复后的 Harness 运行可以成为验证证据。经验证且适用于其他应用的方案，由 Factory Core 升级到共享作业库。

## 首版验收

用一个真实的 W0 As-Is 应用和一个工作包跑通上述流程。工程师可从工作台发起任务，Agent 可通过 MCP 获取对应版本的上下文和方法，Jira、PR、Harness 与验收记录自动关联。后台能指出缺少哪项证据、由谁处理，并在证据齐备后开放下一步。首个 Agent 执行端和企业实例可提供的事件与权限，需要试点验证。
